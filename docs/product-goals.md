# taste.view × TOP1 DESIGN product goals

## Product thesis

Build a compiler-shaped taste system for AI website builders:

```text
public pages + product brief + references + pairwise preferences
                              ↓
                           Taste IR
                    ↙          ↓          ↘
          installable Skill   MCP/API   DESIGN.md / CI policy
                    ↓
        local TOP1 DESIGN execution engine
                    ↓
      isolated candidates → browser evidence → Release Bar
```

`taste.view` is the web intelligence and compilation layer. `top1-design` is the
local execution and verification layer. Private repositories stay local by
default.

## North-star outcome

For an eligible AI/SaaS website project, turn a runnable incumbent into an
evidence-backed, reversible release candidate with human involvement concentrated
at goal/boundary confirmation and final approval.

The commercial claim is not “95% top-tier design.” A validated cohort must meet
all four independent targets:

1. at least 95% of eligible audited units have no blocker/severe visual or
   interaction defect;
2. at least 90% of eligible projects meet their declared Release Bar;
3. at least 70% of all blinded comparisons prefer the Taste Engine version,
   including ties in the denominator;
4. matched human edit time falls by at least 50%.

## Goal 0 — trustworthy local execution kernel

Status: current repository scope

Deliver:

- repository and product-stage diagnosis;
- `greenfield`, `rescue`, and `governed` strategy selection;
- Level 0–5 change policy and adapter eligibility;
- controlled multi-candidate search and blinded ranking;
- recursive evidence scoring with 95 as promotion threshold;
- visual, interaction, responsive, accessibility, and functional Release Bar;
- reversible change-control checks;
- cohort-level product-metric assessment;
- installable harness templates, fixtures, documentation, and deterministic tests.

Acceptance:

- `schema_version: "1.0"` scoring inputs remain compatible;
- a passing release fixture returns exit code 0;
- a valid but failing fixture returns exit code 2;
- severe accepted risk, missing mobile evidence, failed accessibility, broken
  functional flow, or failed change control blocks release;
- the four commercial metrics cannot be collapsed into one aesthetic score.

## Goal 1 — benchmark the wedge before building a platform

Scope: AI/SaaS marketing sites built with React or Next.js and Tailwind.

Deliver:

- 10–20 consented pilot repositories before a 100-brief benchmark;
- matched baseline and Taste Engine tasks with frozen briefs and content;
- desktop/mobile browser matrix and declared primary flows;
- blinded builder comparisons with randomized/reversed presentation;
- human edit-time instrumentation;
- retention ledger: which Agent edits people kept, reverted, or manually changed;
- failure taxonomy across stack startup, product understanding, taste retrieval,
  generation, review, and repair.

Decision:

- proceed when the cohort trend supports all four targets and failures cluster in
  repairable adapter/evidence problems;
- narrow the wedge when one category consistently fails;
- stop or reposition if blind preference and labor savings remain weak despite
  sound engineering gates.

## Goal 2 — Taste IR and compiler contract

Deliver a versioned intermediate representation that separates:

- product truth and target audience;
- media/category/region/time context;
- stable brand taste from transient trends;
- positive references, anti-references, provenance, and rights;
- observed facts from interpretation;
- transferable mechanisms from prohibited surface copying;
- typography, spacing, hierarchy, color/material, motion, interaction, and copy
  rules;
- adapter authority and Release Bar;
- confidence, contradictions, and expiry.

Compile the same Taste IR into:

- a Codex/Agent Skill;
- `DESIGN.md`;
- CI review policy;
- later MCP/API responses.

Acceptance:

- compiled artifacts are reproducible from a pinned IR version;
- contradictory rules are visible, not silently averaged;
- trend evidence can expire without rewriting stable brand rules;
- every reference preserves provenance and anti-copy boundaries.

## Goal 3 — taste.view web MVP

The current repository includes an independent dogfood prototype under
`examples/taste-view/`. It proves the interaction thesis and exercises the
TOP1 protocol; it is not the data-backed production MVP. Promote it into a
separate production repository after Goal 1 produces pilot evidence.

### View

- browse curated work by product type, page task, user goal, brand character,
  region, and time;
- compare two works and explain dimension-level tradeoffs;
- distinguish `popular`, `well-executed`, and `fit-for-this-brief`;
- expose provenance, freshness, and why a principle transfers;
- avoid a generic inspiration-grid experience.

### Compile

- accept a public website URL and structured brief;
- diagnose the incumbent;
- retrieve a relevant reference set;
- ask only a small number of high-information A/B questions;
- produce a versioned Taste IR and preview;
- compile an installable local Skill/package;
- hand off a signed, inspectable task to the local Agent.

Acceptance:

- the website does not require uploading a private repository for normal use;
- the install command installs a complete versioned artifact, not a sentence;
- the user can inspect permissions, references, rules, and Release Bar before
  installation;
- generated artifacts can be revoked or upgraded explicitly.

## Goal 4 — local execution product

Deliver adapters and isolated execution:

- clone or attach a repository without touching the production branch;
- verify startup and primary flow;
- map routes, components, tokens, and blast radius;
- create genuinely different candidates in isolated worktrees;
- run cheap rejection before expensive visual review;
- compare finalists blind;
- repair one evidence-backed defect class per batch;
- emit a minimal patch or draft PR after Release Bar;
- preserve before/after evidence and rollback.

Start with Next.js/React/Tailwind. Add another adapter only after its failure modes
and test contract are explicit.

## Goal 5 — data moat and governance

Accumulate only consented, attributable, useful feedback:

- pairwise preferences and their brief/context;
- failed candidates and defect taxonomy;
- accepted/rejected/edited Agent changes;
- reference usefulness and expiry;
- Release Bar failures and regressions;
- organization-specific approvals.

Separate community upload, candidate taste set, and verified Taste Pack. Community
popularity never automatically becomes a standard.

## One-night deliverable

A strong overnight run can finish Goal 0 and produce the contract for Goals 1–5.
It cannot truthfully finish:

- a live trends corpus;
- copyright and moderation operations;
- production authentication, billing, sandboxing, or GitHub installation;
- real benchmark results;
- evidence that the four commercial targets have been met.

The stopping rule for the overnight run is therefore:

```text
kernel scripts implemented
and templates/examples installed
and complete tests pass
and release/pass/fail paths exercised
and product goals are falsifiable
```

That is a valuable foundation because the next work can collect evidence instead
of extending an untestable vision.
