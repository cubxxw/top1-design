# SEO-facing design protocol

SEO is a product and information-quality constraint, not a visual style.

## Evaluate the system

Check:

- crawlable navigation and links;
- unique, useful page purpose;
- truthful title, heading, description, and structured data;
- accessible semantic markup;
- useful internal linking;
- stable canonical and locale behavior;
- performance and Core Web Vitals;
- indexation intent;
- visible content parity with what search engines receive;
- no mass-produced pages created only to manipulate ranking.

## Design relationship

Strong SEO-facing design makes:

- category and page purpose legible in the first meaningful content;
- headings reflect real information hierarchy;
- proof and examples available as text, not only images or canvas;
- related content discoverable without bloated navigation;
- product screenshots supported by descriptive context;
- long-form reading rhythm and anchors usable;
- conversion actions available without hiding the useful content.

## Automation boundary

Scheduled jobs may:

- monitor indexation, broken links, metadata drift, schema errors, and Core Web Vitals;
- propose internal-link or content-refresh opportunities;
- open a reviewable patch for deterministic technical fixes.

They should not autonomously publish large volumes of generated pages or rewrite high-value editorial content.

Use current official search-engine guidance before changing production behavior.
